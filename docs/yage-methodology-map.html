01共识天花板：正确的废话从哪来

LLM 的默认输出是"共识"——多数人会同意的话。这由训练机制决定，不随模型升级而消失。

双重机制

  • 下一词预测：天然选择最高概率的词 ≈ 大多数人的平均意见
  • RLHF 对齐：惩罚有争议的强观点，奖励平衡、不表态的答案

叠加结果 = "向均值回归"。正确、安全、平庸。

关键区分：两种不对称

  • 信息不对称（知道更多事实）→ 宽研究可解决
  • 认知不对称（知道如何解读）→ 只有个人上下文能解决

AI 能把新手抬到平均线，但对专家几乎无增益——深度天生是非共识的。

"一个是快递员，一个是分析师。" —— 有无个人上下文的两台同等模型，做同一个研究任务的差距
"更聪明的共识仍然是共识。唯一的出路是注入非共识的视角——你的判断标准、品味和来之不易的直觉。" —— 《Why AI Only Gives You Correct Nonsense》, yage.ai/context-infrastructure-en.html

02宽研究：让 53 篇博客一篇不少

所有 LLM 都有一个规律：输出占到上下文窗口的一定比例（50%，有时甚至 20%）就开始偷懒—— 跳句、缩略、丢条目，然后声称完成了。这是架构问题，不是 prompt 问题。

反"角色扮演"多智能体

不写"你是一名资深工程师"这类角色 prompt——LLM 本来就持有全部职业技能，角色设定只会限制它。 正确做法是上下文窗口隔离：不同进程拿不同子问题，只通过文件与主控通信。

像 senior manager 一样管理 AI

  • 不要微观管理，去设计流程
  • 建 5–10 个典型用例做回归测试，对比 prompt 变体
  • 把迭代本身也宽研究化：让子 agent 自反思、给"过去的自己"提建议

03三层记忆：把判断力沉淀成资产

高手说不清自己为什么厉害——大部分是看不见的肌肉记忆。所以系统收集行为数据而非自我报告： 语音转写、会议记录、聊天记录、每一次你对 AI 的纠正。然后按"稳定性"蒸馏：跨情境、跨时间反复出现的判断，才是你真实的认知结构。

"刻意注入你的偏见是重点——培养出来的偏见是深度的来源。把它显式化，还会带来自我认知：看清自己重视什么、忽略什么。" —— context infrastructure 的立场

04激励感知验证：信源不是平等的

信息的价值取决于信源的激励结构。厂商叙事有用，但不能自证。每个关键主张都要追溯到 不因该主张获益的独立证据。

Claim Ledger（主张台账）

每个关键主张一行：主张内容 · 信源层级 · 验证通道（哪类 Tier 3–4 信源能证实/证伪）· 状态。 只有 Tier 3–4 证据能把状态改为 verified / refuted；contested（证据冲突）是合法结果， 应写进报告而非悄悄选边。

读者模式（写作契约）

  • Mode A 内部备忘：读者共享长期上下文 → 跳过常识，只写会改变结论的未知点
  • Mode B 外部论证：零预设读者 → 显式回答 why this matters，最有用的判断放前几段

三问选模式：读者共享上下文吗？要快判断还是要信服？拿掉私有背景报告还成立吗？

06行动清单：从今天开始积累

别人的公理代表别人的视角。以下是启动你自己上下文基础设施的最小路径：

① 数据层（本周）

  • 建一个目录收一切行为痕迹：会议记录、AI 对话导出、你的每次纠正
  • 规则只有一条：本地文件、集中一处

② 蒸馏层（每日/每周 15 分钟）

  • 日：让 AI 读当日变更写观察日志
  • 周：让 AI 去重剪枝、找跨项目模式
  • 不定期：把稳定判断写成一条公理

③ 消费层（持续）

  • 研究任务走 deep-research-agent：成功标准 + claim 台账就是你的判断上下文
  • 每份 runs/ 产物回流数据层，闭环复利
